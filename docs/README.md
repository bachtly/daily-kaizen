# daily-kaizen docs

What the app does today, one short file per feature (what it does, rules, decisions). No API or data model: the code and tests hold those.

| Feature | Covers |
|---|---|
| [logging](features/logging.md) | Log sheet, Day view, Unlogged slots, Fill |
| [tagging](features/tagging.md) | Categories, AI tags, suggestions, learning from my corrections |
| [activities](features/activities.md) | The second label, chips, time per Activity, rename and merge |
| [week-review](features/week-review.md) | Week page, Review done |
| [reminders](features/reminders.md) | Nudge, Review reminder, Quiet hours, push and email |
| [account](features/account.md) | Sign-in, install, offline Local copy, sign-out |

[`design/`](design/README.md) is a frozen archive of the approved designs. A behaviour change updates its feature doc, never the archive. Keep each feature doc under about 60 lines.
